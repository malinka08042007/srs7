# Архитектура проекта

## Общая схема
Проект работает по классической схеме «клиент-сервер».

1. **Браузер (Frontend)**: Пользователь открывает сайт. Браузер загружает HTML, CSS (Tabler) и JavaScript. Все действия (нажатие кнопок, отправка форм) выполняются без перезагрузки страницы через `fetch()`.
2. **Сервер приложений (Gunicorn)**: Принимает HTTP-запросы от браузера и передает их в Django.
3. **Django (Backend)**: Обрабатывает запросы. Проверяет права доступа (авторизация). Выполняет бизнес-логику (например, смену статуса курса). Отдает HTML-страницы или JSON-ответы (через REST API).
4. **База данных (PostgreSQL)**: Хранит все данные (факультеты, курсы, студентов, историю событий). Django общается с ней через ORM.
5. **Статические файлы (WhiteNoise)**: Отвечает за раздачу CSS, JavaScript и картинок в production-режиме.

## Границы взаимодействия
- **Браузер** общается только с сервером по протоколу HTTP/HTTPS.
- **Сервер (Django)** общается с базой данных по внутреннему протоколу.
- **API** возвращает данные в формате JSON, которые JavaScript встраивает в страницу.
