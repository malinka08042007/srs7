# Типичные ошибки и как мы их решали

## 1. Render не видит файл build.sh
Ситуация: при сборке на Render вылезает ошибка "build.sh: No such file or directory".
Почему: проект лежит во вложенной папке (django_auth), а Render ищет файлы в самом корне.
Решение: в настройках Web Service на Render в поле Root Directory прописать название папки, где лежит manage.py (то есть django_auth).

## 2. Ошибка "DisallowedHost"
Ситуация: сайт не открывается, вместо него надпись про неверный заголовок HTTP_HOST.
Почему: в настройках не указан домен, на котором запущен сайт (или переменная окружения не подтянулась).
Решение: в файле settings.py (или в переменных на Render) прописать домен сайта в ALLOWED_HOSTS, например, srs7.onrender.com.

## 3. Ошибка 500 (Server Error)
Ситуация: сайт просто пишет "Ошибка сервера", без подробностей.
Почему: обычно это значит, что не применились миграции, не установилась какая-то библиотека или в коде опечатка.
Решение: включить DEBUG=True в settings.py, чтобы увидеть полный текст ошибки (Traceback) и понять, в каком файле проблема.

## 4. Ошибка с Bootstrap (.map)
Ситуация: при сборке статики (collectstatic) вылетает ошибка, что не найден файл bootstrap.min.css.map.
Почему: в библиотеке Bootstrap не хватает вспомогательного файла карты.
Решение: в settings.py заменить сжатие статики на стандартное (использовать StaticFilesStorage вместо CompressedManifestStaticFilesStorage).

## 5. Ошибка "value too long for type character varying(20)"
Ситуация: при смене статуса через API сервер выдает 400 Bad Request.
Почему: в поле action (которое имеет лимит 20 символов) записывается слишком длинная строка, например, "STATUS_CHANGED: draft -> submitted".
Решение: в models.py увеличить max_length для поля action (например, до 100) и применить миграции.
